Amplify Hosting serves a static website (the `dist/` folder a React or Vite build produces) over HTTPS on an `amplifyapp.com` address, with a global CDN in front. You don't create a bucket, a distribution or a certificate yourself: you create an Amplify **app**, add a **branch**, and deploy your files to it.

"Amplify" is also the name of a wider set of AWS tools for building full-stack apps (libraries, a CLI, backend features). This page is only about **Amplify Hosting**, the part that puts a built site online.

## Key ideas

<KeyConcepts>
  <Concept title="App and branch">An **app** is your website. Each **branch** (like `main`) is a deployable copy with its own URL: `https://main.<app-id>.amplifyapp.com`.</Concept>
  <Concept title="Two ways to deploy">Connect a Git repository and Amplify builds and deploys on every push, or deploy files yourself (**manual deploy**) by uploading a zip of an already-built site.</Concept>
  <Concept title="Rewrites and redirects">Rules that change what a URL serves. Single-page apps need one: any path without a file extension (like `/login`) should return `index.html` with status 200, so React's router can show the right page.</Concept>
  <Concept title="Jobs">Each deployment is a **job** with a status: pending, running, `SUCCEED` or `FAILED`. You can watch it in the console or poll it from the CLI.</Concept>
  <Concept title="CDN and HTTPS included">Amplify Hosting serves your files through a content delivery network and gives you HTTPS automatically TODO(verify). Custom domains can be added later.</Concept>
</KeyConcepts>

## How our projects use it

### DropVault

[DropVault](/projects/dropvault) hosts its React app on Amplify by default (`web_hosting = "amplify"` in Terraform). The README explains why it's the default: it works on brand-new accounts, while the CloudFront option needs AWS Support to verify the account first.

- **Terraform creates the app and branch.** `aws_amplify_app` (named `enclave-dev-web`, platform `WEB`) and `aws_amplify_branch` for `main` with stage `PRODUCTION`.
- **An SPA rewrite rule.** A regex rule sends any path that isn't a real file (not `.js`, `.css`, `.png`...) to `/index.html` with status `200`, so links like `/admin` work when opened directly.
- **A manual zip deploy.** No Git connection: `deploy.sh` builds the app with the new API URL baked in, zips `dist/`, and then:

```bash title="terraform/deploy.sh (simplified)"
aws amplify create-deployment --app-id "$AMPLIFY_APP" --branch-name main   # returns jobId + zipUploadUrl
curl -X PUT -H "Content-Type: application/zip" --data-binary @site.zip "$UPLOAD_URL"
aws amplify start-deployment --app-id "$AMPLIFY_APP" --branch-name main --job-id "$JOB_ID"
aws amplify get-job --app-id "$AMPLIFY_APP" --branch-name main --job-id "$JOB_ID"   # repeat until SUCCEED
```

- **Its URL feeds the rest of the app.** The Amplify address becomes `web_url`, which S3's CORS rules allow and the health check probes.

[Quibble](/projects/quibble) and [this site](/how-this-site-works) don't use Amplify: Quibble serves its frontend straight from S3, and this site uses S3 with CloudFront.

<Callout type="cost" title="How Amplify Hosting is billed">

You pay for build minutes (if Amplify builds your code), for storage of your deployed files (GB per month) and for data served to visitors (per GB) TODO(verify). DropVault builds on your laptop and uploads a zip, so it uses no build minutes.
