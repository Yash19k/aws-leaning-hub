SNS is a **publish/subscribe** (pub/sub) service. You create a **topic**, things **subscribe** to it (an email address, a phone, a Lambda function, a queue), and when anyone **publishes** a message to the topic, SNS delivers a copy to every subscriber. The publisher doesn't need to know who is listening or how many.

That decoupling is the point. Your alarm or your code just says "something happened"; who hears about it is a separate decision you can change without touching code.

## Key ideas

<KeyConcepts>
  <Concept title="Topic">A named channel with an ARN, like a group chat. Publishers send to it; it keeps no history of old messages.</Concept>
  <Concept title="Subscription and protocol">A subscription connects a topic to one endpoint using a **protocol**: `email`, `sms`, `lambda`, `sqs`, `https` and more. One topic can have many subscriptions of different kinds.</Concept>
  <Concept title="Confirmation">An email subscription stays **pending** until the person clicks the 'Confirm subscription' link AWS emails them. Until then, nothing is delivered. This stops anyone signing up a stranger's inbox.</Concept>
  <Concept title="Publish">One API call (`Publish`) with a message and an optional subject. SNS handles delivery and retries to every subscriber.</Concept>
  <Concept title="Fan-out">Publish once, deliver many times. Adding a new subscriber needs no code change in the publisher.</Concept>
</KeyConcepts>

## How our projects use it

### DropVault

[DropVault](/projects/dropvault) sends every alert through one topic, `enclave-dev-alerts`.

- **An email subscription** is created only if you set `alert_email` in `terraform.tfvars`. AWS emails that address a confirmation link first.
- **CloudWatch alarms publish straight to the topic.** The Lambda error and API 5xx alarms notify on both the `ALARM` and the `OK` (fixed) states.
- **The `monitor` Lambda publishes too**, for errors it finds in the logs and failed health checks. It allows at most one email per function every `alert_cooldown_minutes` (15 by default), so a broken deploy can't flood your inbox.
- **Failed deploys.** If `deploy.sh` stops with an error, it runs `aws sns publish` to the topic before exiting.

### Quibble

[Quibble](/projects/quibble) has an `AlertsTopic` with the display name "Quibble alerts", and an email subscription created only when the `AlertEmail` parameter is set.

- **The monitor turns alarms into readable emails.** Alarms invoke the `monitor` Lambda, which adds the matching error log lines and publishes to the topic.
- **A safety net.** If the monitor itself fails, the `quibble-monitor-errors` alarm publishes CloudWatch's plain message straight to the topic.
- **Admin tripwire.** The `api` function publishes when an admin role is granted or removed, a player is banned or deleted, a password is reset, or questions are bulk-deleted (`lib/alerts.js`), in case an admin account falls into the wrong hands.
- **Did they confirm?** `npm run alerts:test` sends a test email and uses `ListSubscriptionsByTopic` to say whether the address has confirmed yet.
