Elastic Beanstalk is the "just run my app" button. You upload your code as a zip (a Node.js, Python, Java, PHP, .NET, Go or Ruby app, or a Docker image) and Beanstalk creates everything around it: [EC2](/services/ec2) instances, a [load balancer](/services/elb), an Auto Scaling group, health monitoring and log collection. Deploying a new version is one command.

Nothing is hidden. Beanstalk builds ordinary AWS resources in your account, using [CloudFormation](/services/cloudformation) behind the scenes, so you can open the EC2 console and see the instances it made.

## Key ideas

<KeyConcepts>
  <Concept title="Application">The top-level container for your project in Beanstalk. It holds versions and environments.</Concept>
  <Concept title="Application version">One uploaded build of your code (a zip in S3). You can roll back to an older version at any time.</Concept>
  <Concept title="Environment">A running copy of one version, with its own URL, e.g. `my-app-prod.ap-south-1.elasticbeanstalk.com` TODO(verify). Many teams have a `staging` and a `prod` environment.</Concept>
  <Concept title="Platform">The language runtime and OS your app runs on, such as "Node.js 22 on Amazon Linux 2023" TODO(verify). AWS updates platforms; you choose when to move.</Concept>
  <Concept title="Single instance vs load balanced">A **single-instance** environment is one EC2 server: cheapest, good for learning. A **load-balanced** environment adds a load balancer and several instances for real traffic.</Concept>
  <Concept title="Web server vs worker">A **web server** environment answers HTTP requests. A **worker** environment pulls jobs from an [SQS](/services/sqs) queue and processes them in the background.</Concept>
</KeyConcepts>

## Where it would fit in our projects

Neither project uses Beanstalk, because both are serverless: no EC2 instances at all. But Beanstalk is a useful mental comparison. [Quibble](/projects/quibble) needed a SAM template with six Lambda functions, two APIs and nine tables to go live. A traditional Express version of the same app could be zipped and deployed to Beanstalk in a few minutes, at the price of an always-on server and a separate database to set up.

## Free Tier and cost

<Callout type="cost" title="How Elastic Beanstalk is billed">

Beanstalk itself has no extra charge. You pay for the resources it creates: EC2 instances, EBS volumes, the load balancer, and any public IPv4 addresses TODO(verify).

- A **load-balanced** environment runs a load balancer around the clock, which is not free TODO(verify). Choose **single instance** while learning.
- Run `eb terminate` (or terminate the environment in the console) when you're done, or the instances keep billing.

</Callout>
