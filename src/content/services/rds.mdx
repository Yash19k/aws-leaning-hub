RDS runs a **relational (SQL) database** for you: MySQL, PostgreSQL, MariaDB, Oracle, SQL Server or Db2. You pick the engine and a size, and AWS installs it, applies patches, takes nightly backups, and can keep a standby copy ready in another data centre. You connect with the same drivers and SQL you'd use on your laptop.

Relational databases store data in **tables** with fixed columns and link tables with **joins**. That's a different model from [DynamoDB](/services/dynamodb), which both our projects use, where you design around the exact questions (access patterns) your app will ask.

## Key ideas

<KeyConcepts>
  <Concept title="DB instance">One database server with an instance class such as `db.t4g.micro`, storage on EBS, and an endpoint like `mydb.abc123.ap-south-1.rds.amazonaws.com` you connect to.</Concept>
  <Concept title="Multi-AZ">A standby copy in another Availability Zone, kept in sync. If the main one fails, RDS switches to the standby automatically, usually within a minute or two TODO(verify). It costs roughly double.</Concept>
  <Concept title="Read replicas">Read-only copies that take reporting and read traffic off the main database. Writes still go to the primary.</Concept>
  <Concept title="Backups and snapshots">Automated daily backups plus transaction logs let you restore to any second within the retention window. Manual **snapshots** are kept until you delete them.</Concept>
  <Concept title="Networking">An RDS database lives in a [VPC](/services/vpc), protected by a security group. Best practice is a private subnet with no public access, reached only by your app.</Concept>
  <Concept title="RDS Proxy">Sits between your app and the database and shares a pool of connections, so hundreds of Lambda functions don't each open their own.</Concept>
</KeyConcepts>

## Where it would fit in our projects

[Quibble](/projects/quibble) keeps everything in nine DynamoDB tables, including leaderboards that it saves pre-computed ("materialised") so reading them is a single lookup. With RDS you could instead compute a leaderboard on the fly with one SQL query (`GROUP BY` player, `ORDER BY` total score), and add new kinds of reports later without changing the tables.

The price: the database runs all the time, the Lambda functions would need to join the VPC to reach it, and you'd want RDS Proxy to handle the burst of connections when a whole class answers at once. Quibble's own question bank even asks how a Lambda function reaches an RDS database in a private subnet.
